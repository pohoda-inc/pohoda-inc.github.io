結論：目安は年間で開発費の15%程度

アプリの保守費用は、年間で開発費の15%程度が一般に語られる目安です（出典は記事末）。

この目安で計算すると、80万円で作ったアプリなら年12万円、月にして1万円です。

Pohoda の保守は、月3万円からです。上の目安より高くなる場合があります。月に使える作業時間を決めて、その中で動くようにしているためです。安いと言うつもりはありません。代わりに、その費用で何をするのかを、次の節から具体的に書きます。

この目安は、保守の中身で大きく変わります。サーバーの費用や新機能の追加は、別の項目として扱われることが多いです。金額だけを比べず、何が含まれるかを見てください。

保守に何が含まれるか

「保守」という言葉は、会社によって指す範囲が違います。Pohoda の範囲を例に、含むものと別料金になりやすいものを分けました。

含むものOS 更新への対応。不具合の調査と小規模な修正。文言や画像の差し替え。ストア更新の申請と審査対応。
別料金になりやすいもの新機能の追加（Pohoda では別見積り）。サーバーや AI、決済など外部サービスの利用料（依頼主の負担）。Apple Developer Program の年会費。24時間の監視や即時の対応。

Pohoda では、月の上限時間を決めています。使わなかった分は繰り越しません。解約は1か月前までの通知です。

新機能の追加が別になるのは、保守と開発で仕事の性質が違うからです。保守は、今あるアプリを今の環境で動かし続ける仕事です。新しい機能は、仕様を決めるところから始まるので、改めて見積りをします。

なぜ公開後に手がかかるのか

私は自社で iPhone アプリ10本を運用しています。2026年の秋だけで、次のことがありました。

  • 新型 iPhone Duo への対応（10月）。折りたたみの iPhone Duo が10月23日に発売されました。9本を Xcode 27.1 でビルドして確認し、コードを変えたのは1本の1行だけで、崩れはありませんでした。ただ、ストア用の画像は別に撮影する必要があります。Apple は2027年4月から、この画像を必須にする予定です。
  • キーボードの不具合（10月）。自前のタブバーが、キーボードと一緒にせり上がる不具合が5本で見つかりました。9本まとめて修正版を提出しました。
  • 年齢区分の新しい必須項目（11月）。Apple が年齢区分の質問に新しい必須項目（ソーシャルメディア）を足しました。未回答のままだと、提出そのものが止まります。回答すれば通りました。
  • サイトの証明書の系統変更（10月）。会社の PC から「安全ではない」と表示される環境が出ました。配信経路を変えて解消しました。
  • データベースの移行（10月）。DriveScape と Insight のデータベースを、Neon から Cloudflare D1 へ移しました。これは外から迫られたのではなく、自分で決めた移行です。サーバーを持つと、こうした作業も出てきます。

どれも、アプリを作った時点の予定にはなかったことです。調べて、直して、提出する。この繰り返しが、公開後の仕事の中身です。

OS や Apple、外部サービスの側が変わると、アプリは変えていなくても手を入れる必要が出ます。私の契約では、検収の合格後に公開された OS・端末・第三者サービスの変更が原因のものは、無償の修補の対象外にしています。そういう変更に対応するのが、保守です。

端末内で完結するアプリと、サーバーのあるアプリの差

保守の重さは、アプリの作りで変わります。

端末内で完結するアプリは、主な作業が OS の更新への対応とストア関係です。サーバーや AI を持つアプリは、それに加えて、サーバーの更新、データベースや証明書の変更、外部サービスの料金や仕様の変更を見る必要があります。上の例で言えば、証明書とデータベースの件がそれです。

外部サービスの料金は、使われ方で上下します。保守費に含めて固定にするのか、実費を別に請求するのか、これも契約の前に決めておくと揉めません。

サーバーや API の利用料は、保守費とは別にかかります。見積りの段階で、どちらの作りなのかを確認してください。

保守を頼まないとどうなるか

すぐに動かなくなるわけではありません。公開済みのアプリは、そのまま使えるのが普通です。

困るのは、次に更新を出すときです。OS の変更や、Apple の必須項目の追加（上の年齢区分の件）で、提出が止まることがあります。サーバーのあるアプリは、外部サービスの変更で動きが変わることもあります。

そのときに、直せる人がいるかどうかです。いなければ、探すところから始まります。探す時間が長いほど、アプリは更新されないまま置かれます。

保守の契約で確かめること

  • 月の上限時間と繰り越し。何時間まで含むのか。使わなかった分は繰り越せるのか（Pohoda は繰り越しません）。
  • 返信の速さ。問い合わせにいつまでに返事があるのか。Pohoda は2営業日以内です。
  • 解約の条件。いつまでに伝えれば解約できるのか（Pohoda は1か月前まで）。
  • 作業報告。何をしたかが、報告で分かるか。
  • 修正したコードの権利。保守で直したコードが、誰のものになるか。
  • 開発者が辞めたときの引き継ぎ。ソースコードと Apple のアカウントが、自分の手元にあるか。ここが他人の名義だと、開発者がいなくなった時点で、更新を出せなくなります。

自分で保守する選択肢

自分で保守することもできます。ソースコードと Apple のアカウントが手元にあり、Xcode でビルドして、App Store Connect から提出できる人なら可能です。OS の更新があるたびに、動作を確かめる時間を取れることも条件になります。自分で見られないなら、頼める人を先に決めておくほうが、止まったときに慌てずに済みます。

よくある質問

アプリの保守費用はいくらですか？

一般には、年間で開発費の15%程度が目安として語られます。保守の内容で大きく変わり、サーバーの費用や機能追加は別の項目として扱われることが多いです。Pohoda の保守は月3万円からです。

保守は必ず必要ですか？

必須ではありません。公開したアプリがすぐ動かなくなるわけではないからです。ただし、OS の更新や Apple の必須項目の変更で、次の更新の提出が止まることがあります。そのときに対応する人が手元にいるかどうかが、判断の分かれ目です。

他社が作ったアプリの保守も頼めますか？

ソースコードを見せていただいてから、お受けできるかを判断します。中身を見る前に、お受けするとはお約束できません。まずはご相談ください。

24時間対応はできますか？

していません。24時間の監視や即時の対応は、保守の範囲に含めていません。お返事は2営業日以内です。

保守を頼まず、自分で保守できますか？

できます。ソースコードと Apple のアカウントが手元にあり、Xcode でビルドと提出ができる人なら可能です。自分で見られない場合は、引き継ぎができる状態かどうかだけは、契約の時点で確かめてください。
